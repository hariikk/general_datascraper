Data Extractor

Runs

Every new Search gets its own run folder, including its search results, extracted data, checkpoint, PDFs and figures. Loading a saved run switches the app back to that folder; nothing runs until you click a button.

Load an old run, then use Refresh search to merge new results into it. A normal Search always starts a new run. The active run cannot be deleted until you load another one.

1 Search for papers

Combine rows with AND/OR/NOT and groups with AND/OR/NOT. A group set to NOT is excluded from the part of the query before it, so A AND B NOT (predatory OR questionable) finds A and B while dropping anything that matches the NOT group. Select rows or groups with the checkboxes, then wrap them into a nested group. Click a group header to cycle its selection (group → members → group). Multi-word terms are quoted automatically.

Query preview (empty query)

Four digits (e.g. 2015). Leave a box blank for no limit.

Point at a folder of PDFs to extract them without a search (clear the search terms and websites), or combine them with a normal online search. PDFs are copied into output/pdfs/, so the output stays self-contained.

One journal name per line. Matching is case-insensitive and uses substrings, so differences in capitalisation, spacing, or extra punctuation are caught too. It is applied after the search, to the combined results from every website; papers with no journal name are never excluded.

A normal Search creates a new run folder and replaces that folder's dataset. To add new results to an existing run, load it in Runs above and click Refresh search.

2 Extract data from the papers

This reads the open-access full texts of the papers you found and asks the model to pull out what you ask for. Closed papers are logged separately.

Rewrites the wording only; nothing runs until you click Extract data.

Figures and tables are selected from this goal. To collect them, ask for figures, images or tables in the goal above (e.g. “Find figures showing current traces for each mutation”).

Paper key, row number, evidence/page and PDF columns are added automatically; those names are reserved.

Use Table rows when the paper reports a table and you want every table row kept separate. Individual records is the safer default for prose and mixed papers.
